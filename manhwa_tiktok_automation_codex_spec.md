# Manhwa TikTok Automation App

## Codex Implementation Specification

## 1. Objective

Build a Windows desktop application that automates the repetitive
editing work for vertical manhwa/webtoon recap videos.

The user will manually: 1. Prepare the narration/script. 2. Generate the
narration audio on the ElevenLabs website. 3. Run the narration through
ElevenLabs Speech-to-Text. 4. Export the ElevenLabs transcript as JSON
with timestamps enabled. 5. Import the narration MP3, timestamped JSON,
and manhwa panels into this application. 6. Review/rearrange panels and
override effects if necessary. 7. Preview and render the final video.

The application handles: - Panel import and organization - Drag-and-drop
panel rearranging - Sequential numbering and optional physical file
renaming - ElevenLabs JSON parsing - Narration timing - 2--3 word
captions - Word-level caption highlighting - Automatic panel timing -
Automatic alternating motion effects - Manual effect overrides -
Slide-effect swap logic - Panel/video preview - FFmpeg rendering -
Project save/load

The final output is intended primarily for TikTok and similar vertical
short-form platforms.

------------------------------------------------------------------------

## 2. Technology Stack

Use the following stack unless there is a strong technical reason to
change it:

-   **Language:** Python 3.12+
-   **Desktop UI:** PySide6
-   **UI styling:** Qt Style Sheets (QSS)
-   **Video/audio rendering:** FFmpeg
-   **Image handling/thumbnails:** Pillow
-   **Transcript source:** ElevenLabs Speech-to-Text JSON export
-   **Narration source:** MP3 generated manually using ElevenLabs
-   **Subtitle rendering:** ASS subtitles generated by Python and burned
    with FFmpeg
-   **Project persistence:** JSON
-   **Windows packaging:** PyInstaller

Do not use Electron, React, MoviePy, or a browser-based frontend for the
initial implementation.

FFmpeg should be invoked from Python using `subprocess`.

## 6. Panel Organizer

### Supported image formats

Support at least:

-   `.jpg`
-   `.jpeg`
-   `.png`
-   `.webp`

### Import behavior

Allow: - File picker import - Drag-and-drop import - Adding more images
after initial import

Generate thumbnails asynchronously.

Do not permanently modify source images during import.

### Initial numbering

Imported images receive sequential display numbers:

``` text
001
002
003
004
...
```

Keep the original filename and original path in project state.

### Rearranging

The user must be able to drag thumbnails to reorder them.

Example:

``` text
Before:
001 002 003 004 005

User moves panel 005 between 002 and 003.

New logical order:
001 002 005 003 004

Displayed sequence numbers are recalculated:
001 002 003 004 005
```

The sequence number represents the current project order, not
necessarily the original filename.

### Organizer features

Implement: - Drag-and-drop reordering - Add panels - Remove panels -
Multi-select - Undo - Redo - Reset to original order - Apply/Rename
Panels

### Physical renaming

Do not rename files automatically merely because their UI order changed.

Provide an explicit **Apply/Rename Panels** action.

When invoked, rename files safely using a two-stage operation:

``` text
original filename
→ unique temporary filename
→ sequential filename
```

Example:

``` text
page_a.jpg → __tmp_uuid_a.jpg → 001.jpg
page_b.png → __tmp_uuid_b.png → 002.png
page_c.webp → __tmp_uuid_c.webp → 003.webp
```

Preserve the original file extension.

Use temporary unique filenames to avoid collisions.

## 9. ElevenLabs JSON Parser

The tested ElevenLabs JSON structure has:

``` json
{
  "language_code": "eng",
  "segments": [
    {
      "text": "Then I'd ",
      "start_time": 0.22,
      "end_time": 0.66,
      "speaker": {
        "id": "speaker_0",
        "name": "Speaker 0"
      },
      "words": [
        {
          "text": "Then",
          "start_time": 0.22,
          "end_time": 0.4
        },
        {
          "text": " ",
          "start_time": 0.4,
          "end_time": 0.5
        },
        {
          "text": "I'd",
          "start_time": 0.5,
          "end_time": 0.62
        }
      ]
    }
  ]
}
```

### Parser requirements

Extract: - Language - Segments - Segment text - Segment start/end -
Individual word text - Individual word start/end

Whitespace can appear as its own word entry:

``` json
{
  "text": " ",
  "start_time": 0.4,
  "end_time": 0.5
}
```

Ignore whitespace-only entries when creating the logical spoken-word
list.

However, preserve timing gaps between real words.

Do not assume speech is continuous.

Example:

``` text
"title?" ends at 11.52
"I'm" begins at 12.40
```

This represents a real pause and must not be collapsed.

### Floating-point handling

Input may contain values such as:

``` text
26.779999999999998
```

Keep sufficient numeric precision internally but round display values to
approximately three decimal places:

``` text
26.780
```

## 10. Caption Engine

### Caption grouping

Default caption size:

**2--3 spoken words per caption group.**

Do not use character count as the primary grouping mechanism.

Use actual spoken words extracted from the ElevenLabs JSON.

Example:

``` text
There's no
real reason to
hate Aiselin.
```

Prefer natural phrase boundaries when practical rather than blindly
alternating 2 and 3 words.

Do not split a word.

Punctuation should stay attached to its word.

The caption engine should be deterministic.

### Caption timing

Caption timing must come from the actual word timestamps.

For a caption group, use: - Start = first word's `start_time` - End =
last word's `end_time`

Preserve pauses. Do not extend the next caption backward into silence.

### Default caption style

Use a TikTok-style preset:

``` text
Font: TikTok Sans Bold/ExtraBold if available
Case: ALL CAPS
Words per caption: 2–3
Normal text: White
Currently spoken word: Yellow
Outline: Thick black
Shadow: Subtle
Alignment: Center
```

Do not depend on a bundled proprietary font. If TikTok Sans is not
legally or technically available, allow the user to select an installed
font and provide a reasonable fallback such as a bold sans-serif.

### Word highlighting

Within each 2--3 word caption, highlight the currently spoken word
yellow using the individual ElevenLabs word timestamps.

Example:

``` text
GIFT READS
```

When `GIFT` is spoken: - GIFT = yellow - READS = white

When `READS` is spoken: - GIFT = white - READS = yellow

The implementation may use ASS subtitle events/tags or another
FFmpeg-compatible method, but timing must remain synchronized to the
word timestamps.

### Caption settings UI

Allow changing: - Font - Font size - Vertical position - Normal color -
Highlight color - Outline thickness - Shadow - ALL CAPS on/off - 2-word
/ 3-word / automatic 2--3-word grouping

## 11. Panel Timing Engine

Caption timing and panel timing are separate.

Do not change the panel every time a 2--3 word caption changes.

Panels should remain visible long enough for slow motion effects to be
visually comfortable.

The timing engine should use: - Narration duration - Word timestamps -
Segment boundaries - Natural pauses - Number of available panels

Avoid panel cuts in the middle of spoken words.

Prefer cuts: 1. During/near pauses 2. Between sentences or phrases 3.
Between words 4. Never inside a word

The automatic result should look similar to:

``` text
001.jpg    0.000 → 3.240
002.jpg    3.240 → 6.100
003.jpg    6.100 → 9.640
```

The review UI must allow manual timing adjustment later.

Keep the timing engine modular because more advanced panel-to-dialogue
matching may be added later.

## 13. Zoom In Effect

Zoom In is an animated zoom.

Default:

``` text
Start scale: 1.00x
End scale: approximately 1.05x
```

Keep the zoom subtle.

Default anchor/focal position:

``` text
Center
```

Allow the user to change the zoom anchor per panel:

``` text
Center
Top
Bottom
Left
Right
Custom
```

Changing the Zoom In anchor must not modify any other panel.

Changing a panel to or from Zoom In must not invoke slide swap logic.

------------------------------------------------------------------------

## 14. Slide Effects

Slides are pans, not transitions.

For slide effects, first apply a small **static pre-zoom** so there is
room to move.

Default approximate pre-zoom:

``` text
1.05x
```

This pre-zoom is not animated.

Then pan slowly.

### Slide Left

``` text
Start: slightly toward the RIGHT side of the enlarged image
End: slightly toward the LEFT side
```

### Slide Right

``` text
Start: slightly toward the LEFT side
End: slightly toward the RIGHT side
```

### Slide Up

``` text
Start: slightly toward the BOTTOM
End: slightly toward the TOP
```

### Slide Down

``` text
Start: slightly toward the TOP
End: slightly toward the BOTTOM
```

The desired movement is subtle and slow.

Do not create a large pre-zoom that causes fast-looking movement.

The renderer must calculate safe movement limits based on: - Source
dimensions - 9:16 output viewport - Scale - Direction

Never expose black, transparent, or empty edges.

Movement distance should be constrained by available overscan.

The panel duration determines movement speed: a longer panel should
traverse the same intended range more slowly rather than moving farther.

## 16. Slide Swap/Replacement Rule

The four slide effects form a rotation group:

``` text
Slide Left
Slide Right
Slide Up
Slide Down
```

Within each four-slide rotation group, automatic assignment should
attempt to keep all four directions represented once.

If the user changes one slide to another slide already present in that
group, swap/reassign the displaced effect.

Example:

``` text
Before:

Panel A → Slide Left
Panel B → Slide Right
Panel C → Slide Up
Panel D → Slide Down
```

User changes:

``` text
Panel B:
Slide Right → Slide Up
```

Result:

``` text
Panel A → Slide Left
Panel B → Slide Up       # user's choice
Panel C → Slide Right    # displaced effect
Panel D → Slide Down
```

The user's manually selected panel must remain exactly as selected.

### Zoom exception

Zoom is independent.

If:

``` text
Zoom In → Slide Right
```

only that panel changes.

Do not modify another panel.

If:

``` text
Slide Left → Zoom In
```

only that panel changes.

Only **Slide → Slide** changes trigger the swap/replacement behavior.

Keep this rule isolated in the effect engine and cover it with unit
tests.

## 19. FFmpeg Rendering Pipeline

Python should generate the FFmpeg render instructions.

Conceptual panel pipeline:

``` text
Source image
    ↓
Calculate scale required to cover 9:16
    ↓
Apply effect-specific scale/overscan
    ↓
Calculate safe crop/pan coordinates
    ↓
Animate zoom or position for panel duration
    ↓
Output 1080x1920 frames
    ↓
Hard cut to next panel
```

Final composition:

``` text
Rendered panel sequence
+
voice.mp3
+
ASS captions
    ↓
FFmpeg
    ↓
final.mp4
```

No transition filters between panels.

Use temporary/intermediate files safely and clean them up after
successful rendering.

Render progress should be reported back to the UI.

Rendering must run outside the Qt main thread.

Support cancellation where practical.

## 22. Error Handling

The application should fail gracefully.

Handle at least: - Missing FFmpeg - Unsupported image - Corrupted
image - Missing audio - Invalid ElevenLabs JSON - JSON without
timestamps - Missing source files when reopening a project - FFmpeg
render failure - Output path permission errors - Renaming collisions -
User cancellation

Show actionable UI error messages instead of raw tracebacks.

Log technical details to a log file for debugging.

## 23. Performance Requirements

The application may handle many manhwa panels.

Therefore: - Generate thumbnails asynchronously. - Cache thumbnails. -
Do not load every full-resolution image permanently into RAM. - Do not
perform FFmpeg work on the Qt UI thread. - Use lazy loading where
useful. - Keep scrolling/reordering responsive with large panel sets. -
Avoid unnecessary re-encoding during ordinary UI changes.

## 28. Core Behavioral Rules

These rules should not be changed without explicit instruction:

1.  Output is primarily 9:16.
2.  Default final resolution is 1080x1920.
3.  Panels use hard cuts, not transitions.
4.  Caption groups contain approximately 2--3 words.
5.  Caption timing comes from actual ElevenLabs word timestamps.
6.  The currently spoken caption word is highlighted yellow by default.
7.  Panel timing is separate from caption timing.
8.  Default effect cycle is Zoom In → Left → Right → Up → Down → repeat.
9.  Zoom In is subtle.
10. Slides use a subtle static pre-zoom before movement.
11. Slide pre-zoom itself is not animated.
12. Slides move slowly from the side opposite their movement direction.
13. Empty image edges must never become visible.
14. Slide-to-slide overrides use the swap/replacement rule.
15. Changes involving Zoom In do not modify other panels.
16. Users can review and override automatic effects before rendering.
17. Users can rearrange panels before rendering.
18. Physical panel renaming occurs only when explicitly requested.
19. Source images should not be destructively modified unnecessarily.
20. FFmpeg is the rendering engine; Python/PySide6 controls the
    application and editing logic.

------------------------------------------------------------------------

## 29. Implementation Philosophy

Favor reliability and deterministic behavior over unnecessary
complexity.

The application is intended to remove repetitive editing work while
keeping the user in control of creative decisions.

Automatic decisions must be visible and editable before the final
render.

Keep components modular so future versions can add features such as: -
smarter panel-to-narration matching - additional motion effects -
multiple caption presets - automatic script parsing - direct ElevenLabs
API support - background music/SFX - automatic TikTok export/upload
workflows

Do not implement these future features until the core workflow described
in this specification is stable.
